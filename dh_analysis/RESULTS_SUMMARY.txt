====================================================================
KEY OBSERVATIONS
====================================================================

1. PUBLIC KEY SIZE RELATIONSHIP:
   - Public key size ≈ 2 × (bit_size / 8) + DER_overhead
   - DER overhead ≈ 30-50 bytes (decreases relatively with larger keys)

2. WHY 2× THE BIT SIZE?
   DH public keys contain TWO major components:
   a) Parameters: prime p (~bit_size)
   b) Public value: y = g^x mod p (~bit_size)
   Total ≈ 2 × bit_size

3. FFDHE vs MODP:
   - Same bit size → nearly identical public key size
   - Main differences are in prime number generation
   - FFDHE (RFC 7919) is recommended for modern applications
   - MODP (RFC 3526) used for backward compatibility

4. SECURITY RECOMMENDATIONS:
   - Minimum: 2048 bits
   - Recommended: 3072 bits
   - ≤1536 bits: INSECURE, do not use

====================================================================
OPENSSL COMMANDS USED
====================================================================

1. GENERATE NAMED GROUP PARAMETERS:
   openssl genpkey -genparam -algorithm DH \
       -pkeyopt dh_param:ffdhe2048 -out ffdhe2048.pem

2. GENERATE CUSTOM PARAMETERS:
   openssl genpkey -genparam -algorithm DH \
       -pkeyopt dh_paramgen_prime_len:2048 -out custom_2048.pem

3. VIEW PARAMETERS:
   openssl pkeyparam -in ffdhe2048.pem -text -noout

4. GENERATE KEY PAIR:
   openssl genpkey -paramfile ffdhe2048.pem -out ffdhe2048_key.pem

5. VIEW KEY DETAILS:
   openssl pkey -in ffdhe2048_key.pem -text -noout

6. EXPORT PUBLIC KEY (DER):
   openssl pkey -in ffdhe2048_key.pem -pubout \
       -outform DER -out ffdhe2048_pubkey.der

7. ANALYZE DER STRUCTURE:
   openssl asn1parse -in ffdhe2048_pubkey.der -inform DER

DER STRUCTURE (Example: ffdhe2048)
====================================================================

SEQUENCE (549 bytes total)
  ├─ SEQUENCE (Algorithm Identifier, 279 bytes)
  │  ├─ OBJECT IDENTIFIER: dhKeyAgreement (1.2.840.113549.1.3.1)
  │  └─ SEQUENCE (DH Parameters)
  │     ├─ INTEGER: p (prime, 257 bytes / 2048 bits)
  │     └─ INTEGER: g (generator, 1 byte, value=2)
  └─ BIT STRING (Public Key Value, 262 bytes)
     └─ INTEGER: y = g^x mod p (~2048 bits)

Components:
- Prime modulus p: 2048 bits = 256 bytes (+ 1 byte padding) = 257 bytes
- Generator g: 1 byte (usually 2 or 5)
- Public key y: ~2048 bits ≈ 256 bytes
- DER overhead: ~35 bytes (structure tags, lengths, OID)
- Total: 257 + 1 + 256 + 35 = 549 bytes ✓

====================================================================
FORMULA
====================================================================

Public Key Size (bytes) ≈ 2 × (bit_size / 8) + overhead

Where:
- bit_size: Size of prime modulus p
- First term: Parameters (mostly prime p)
- Second term: Public key value y
- overhead: DER encoding structure (~30-50 bytes)

For 2048-bit DH:
  ≈ 2 × (2048 / 8) + 40
  ≈ 2 × 256 + 40
  ≈ 552 bytes ✓ (observed: 552-553 bytes)
